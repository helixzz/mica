# 待决策与待验证清单

> **用途**：把所有需要业务判断、或需要人工验证的事项集中一处，便于开会讨论。
> **状态**：截至 v1.69.2。凡是不需要业务判断的工作都已完成，本清单之外没有待实现的开发任务。
> **怎么用**：每条都给了**背景**、**选项**、**我的建议**和**影响范围**。只需要回答"选哪个"。

---

## A. 阻塞开发（需要你拍板）

### A1. 两种"报价"来源要不要合并

**背景**：价格记录里的来源字段，实际有 5 种值在写，而 API 白名单只声明了 4 种：

| 写入者 | 值 | 条数（生产） |
| :--- | :--- | :--- |
| 价格页手工录入 | `manual` | — |
| 询价报价（v1.68.1 起） | `quote` | 5 |
| 转换采购订单 ×3 处 | `actual_po` | 134 |
| **采购申请报价确认弹窗** | `supplier_quote` | 109 |
| Excel 导入 | `excel_import` | 0 |
| 旧的询价路径 | `rfq_quote` | 15（已废弃） |

**问题**：`supplier_quote`（采购申请明细里的报价）与 `quote`（询价单报价）语义是否等同？

**选项**：
1. **合并为 `quote`** —— 口径统一，但会改变 124 条历史记录的展示，且需同时改采购申请报价的幂等键（改不好会重复插入价格记录）
2. **保持两种，补进白名单并翻译界面** —— 零风险，但口径继续分叉
3. **保持两种，但在报表层面归并展示** —— 折中

**我的建议**：**选项 2 或 3**。理由：`CHANGELOG` 里你们自己写过「`supplier_quote` 数据可信度低于 `actual_po`」——如果两种报价的可信度在业务上也不同，合并不但无益，还会丢掉区分能力。除非你确认两者在比价时应当一视同仁。

---

### A2. 15 条历史报价记录缺少录入人 —— **已诊断：无需动作**

**背景**：v1.68.1 之前，询价报价插入价格记录时绕过了共享路径，`entered_by_id` 一直是空。生产上有 15 条 `rfq_quote` 记录处于这种状态。

**我做了什么**：跑了一次只读诊断（不改任何数据），看这些记录是否真的漏出了基准计算。

**结果**：**没有漏**。

- 这 15 条分布在 10 个物料上
- 10 个物料**全部都有基准记录**，其中多数 `sample_size = 1`——那唯一一条样本就是这些 legacy 记录
- 原因：基准计算（`_refresh_benchmark`）只按物料与时间窗口过滤，**从不看来源类型**

所以「重算基准」这个动作**不会产生任何变化**。唯一缺的只是「谁录的」这个审计字段，而旧代码没有记录，库里无从回填。

**结论**：**不需要做任何事**。把这一段写进文档即可，不必修正数据。

### A3. Excel 导入的价格来源保留还是删除

**背景**：`excel_import` 这个来源值只有一个后台接口在写，**没有前端入口**，生产 0 条。

**选项**：
1. **保留**并加进白名单与界面标签（已加白名单）
2. 删除该写入路径

**我的建议**：**选项 1（保留现状）**。它无害，且将来若要批量导入历史价格会用到。

## B. 需要你或同事验证（不阻塞，但影响功能可用性）

### B1. 扫描报价识别的实际效果（**管线已在生产验证通过**）

**已验证（2026-10-21，生产真实模型 DeepSeek V4.1 Flash）**：用一份合成的打印体报价单跑完整链路，结果全对：

| 检查项 | 结果 |
| :--- | :--- |
| 5 行明细 | 全部识别，行号/物料/数量/单价/税率/交期均正确 |
| 表头 | 供应商 `Dell China Ltd.`、币种 `CNY` 正确 |
| 税率转换 | `13%` → `0.13` 正确 |
| 页数 | 1/1 |
| 置信度 | 0.99 |
| 勾稽告警 | 无（金额自洽） |

也就是说：**光栅化 → 视觉模型 → JSON 解析 → 行合并 → 金额勾稽 整条链路是通的**。

**仍需真实样本**：上面的样本是打印体 PDF，不是盖章扫描件。真实场景的难点在于扫描质量、倾斜、印章遮挡、手写批注，这些我无法用合成数据模拟。

**建议**：拿一份真实回传件试一次，重点看：

1. 每行价格是否仍然正确
2. 置信度是否会下降到警示区间（低于 70% 会标黄）
3. 金额勾稽是否能抓到识别错误

**如果效果不好**：管理员可以在后台改提示词（v1.69.2 起生效，不用发版），这比换模型便宜得多。

---

### B2. 询价单模板的列安排

**背景**：v1.65.0 起按采购提供的模板生成询价单。表头与明细自动填充，单价/税率/交期/质保留空给供应商。

**需要确认**：哪一列该预填、哪一列该留白。模板列是逐格对照原表实现的，但**业务口径只有你们知道**。

---

### B3. 合同付款计划的显示范围

**背景**：采购订单页的付款计划**有意**同时显示「订单自己的期次」和「关联合同的期次」（代码注释：不合并会漏掉合同的期次）。

**需要确认**：这是期望的行为吗？如果订单页只想看订单自己的期次，需要调整。v1.69.0 已修好"在订单页执行合同期次会失败"的问题，所以混合展示现在是可用的。
