# API 接入（Personal Access Token）

Mica 的网页界面不是唯一入口。当你要让**脚本、外部系统或 AI Agent** 读写 Mica 数据时，用 **API 令牌（Personal Access Token，简称 PAT）**：一个长期有效、可以随时撤销的凭据。

本页面向"要发一个令牌给别人用"的人。完整的技术接入文档（端点契约、字段、错误码、稳定面承诺）见仓库里的 [docs/API.md](https://github.com/helixzz/mica/blob/main/docs/API.md)。

---

## 什么时候需要 API 令牌

| 场景 | 例子 |
|---|---|
| 定时脚本 / 运维自动化 | 每晚导出采购台账、检查超期未交货的 PO |
| 外部系统对接 | 把 Mica 的审批结果同步到内部看板 |
| AI Agent | 让 Agent 读 PR / PO 做汇总、排查异常 |
| 个人命令行工具 | 用 `curl` 查数据，不必每次开浏览器 |

**不需要**令牌的场景：日常网页操作。你的登录态（JWT）和 PAT 走同一套权限判定，网页该看到的，令牌也看到；网页看不到的，令牌同样看不到。

---

## 创建你的第一个令牌

1. 登录 Mica
2. 在左侧导航打开 **API 令牌**（地址是 `/settings/api-tokens`）
3. 点击**新建令牌**，填写：
   - **名称**：给未来的自己看的用途标签，例如 `ci-inspect-script`、`agent-pr-triage`
   - **权限范围**：只读或读写
   - **有效期**：天数；留空使用系统默认（默认 90 天，最长 365 天）
4. 点击创建，页面会显示一次完整的令牌字符串

### 立刻保存明文

明文只在创建（或轮换）的那一次显示。**关闭弹窗后就再也看不到**，列表里只有前缀和状态。请立刻把它存进密码管理器 / CI secret / 服务器环境变量。

```
mica_pat_<prefix>_<secret>
```

- 前缀部分（`mica_pat_xxxx`）可以安全展示，用于在列表里辨认
- 后半段 secret 是真正的凭据，等同于你的密码
- 不要贴进聊天、issue、工单、代码仓库或 AI 对话里。一旦怀疑泄漏，直接撤销或轮换

## 权限范围怎么选

| 权限范围 | 能做什么 | 建议 |
|---|---|---|
| `read` | 只读。调用写操作会被拒绝 | **默认选它**。巡检、报表、导出、AI 查询都用 `read` |
| `write` | 读写，等价于"你在 API 里能做的一切" | 只有确实要写入（建 PR、提交审批、上传附件）才用，并设更短的有效期 |

两点需要知道：

- 令牌的权限**不会超过你本人**。`write` 令牌也只在你自己的角色与部门可见范围内工作。
- 有一批"查询语义的 POST"（搜索、导出、洞察、AI、仪表盘）在只读令牌下**依然允许**——它们按 HTTP 语义用了 POST，但不写业务数据。所以只读令牌能覆盖绝大多数读场景。

---

## 令牌不能用在哪里

以下操作**任何令牌都做不了**，必须由人在网页界面上完成（这是刻意的设计，用来防止凭据自己给自己提权）：

- **后台管理**（系统参数、用户与角色、审计日志查询）
- **单点登录与登录/注册/改密**类端点——唯一例外是查询"我是谁"（`GET /api/v1/auth/me`），可以用令牌探活
- **不能创建权限比自己更大的令牌**：只读令牌无法签发读写令牌

另外，**实时通知的 WebSocket 通道目前只接受网页登录态**，不支持令牌。

## 查看、轮换与撤销

在 **API 令牌**页面的列表里可以看到每个令牌的名称、前缀、权限范围、有效期、最近使用时间与 IP、以及是否过期/已撤销。

| 操作 | 什么时候做 |
|---|---|
| **轮换** | 定期更换，或怀疑泄漏。轮换会立刻签发新 secret 并使旧 secret 失效——不需要先撤销，因此不会出现服务中断窗口 |
| **撤销** | 脚本下线、人员离职、令牌不再需要。撤销立即生效，记录会保留在审计日志中 |
| 什么也不做 | 令牌到期自动失效，无需人工处理 |

**清理建议**：定期看一眼"最近使用时间"。长期不用的令牌可以直接撤销——每个不用却存在的凭据都是一份多余的风险。

## 限流与审计

- **限流按令牌计算**，默认每分钟 600 次请求。超限会收到 `429`，响应里带 `Retry-After` 头（等待秒数）。发现某个脚本总是撞限流，先降低它的并发，再联系管理员调整配额。
- **令牌的创建、轮换、撤销都会写入审计日志**，管理员可以在后台审计日志里查到"谁在什么时候创建/撤销了哪个令牌"。
- **逐请求的详细审计默认关闭**。如果某个窗口期需要完整调用链留痕（例如审计检查），请管理员打开对应开关。

---

## 管理员视角

- **全站令牌列表**：管理员可以查看所有人的令牌，支持按用户过滤、是否包含已撤销、分页；也可以强制撤销任意令牌（例如员工离职时）。
- **系统参数**：在 [系统管理控制台](admin/03-system-console.md) 的"系统参数"页，`api` 分类下可以调整：
  - 每用户令牌数上限（默认 10）
  - 默认有效期（90 天）与最长有效期（365 天）
  - 每分钟请求上限（600）
  - 逐请求审计开关（默认关闭）
  - 只读令牌仍允许的 POST 路径白名单

  这些调整**立即生效，不需要重启服务**。
